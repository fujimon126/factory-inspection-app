# 工場点検アプリ

スマートフォンのブラウザで動く工場設備の点検記録アプリです。
点検結果は端末に保存され、Googleスプレッドシートへ自動送信されて進捗が可視化されます。
電波の届かない工場内でもオフラインで入力でき、通信が回復したときにまとめて送信されます。

---

## 1. ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリの画面（点検／履歴／進捗／設定の4タブ） |
| `css/style.css` | スマホ向けデザイン（大きめのタップ領域・判定色分け） |
| `js/data.js` | **マスターデータ**。機械22種と各機械の点検項目（点検場所の名称はアプリの設定画面で登録します） |
| `js/store.js` | データ保存（端末内）とスプレッドシート送受信 |
| `js/app.js` | 画面の動作（入力・集計・CSV出力など） |
| `manifest.json` / `sw.js` / `icons/` | ホーム画面追加とオフライン動作のための設定 |
| `gas/コード.gs` | **スプレッドシート側のプログラム**（Google Apps Script） |
| `.claude/serve.ps1` | 動作確認用の簡易サーバー（PC確認用。運用には不要） |

点検項目を追加・変更したいときは `js/data.js` だけを直せば全画面に反映されます。

> **工場名について**：拠点名はプログラムに書き込まず、アプリの「設定 → 点検場所の登録」で入力する方式です。
> 入力した名称は使用する端末の中だけに保存されるため、このソースコードを公開しても社名・拠点名は外部に出ません。

## 2. スプレッドシート連携の設定（最初に1回だけ）

1. Googleドライブで**スプレッドシートを新規作成**（名前は「工場点検記録」など）
2. メニューの **拡張機能 → Apps Script** を開く
3. 表示されたコードを全部消し、`gas/コード.gs` の中身を貼り付けて保存（💾）
4. 上部の関数リストから **`初期設定`** を選び **▶ 実行**
   - 初回は権限の確認が出ます → 「権限を確認」→ 自分のアカウントを選択
   - 「このアプリは確認されていません」と出たら **詳細 → （プロジェクト名）に移動** → 許可
   - 実行すると `点検記録` `点検明細` `進捗ダッシュボード` の3シートが自動作成されます
5. 右上の **デプロイ → 新しいデプロイ** → 歯車から **ウェブアプリ** を選択
   - 次のユーザーとして実行： **自分**
   - アクセスできるユーザー： **全員**
   - 「デプロイ」を押し、表示された **`https://script.google.com/macros/s/.../exec`** をコピー
6. アプリの **設定タブ** を開き、コピーしたURLを「GAS ウェブアプリURL」に貼り付けて **設定を保存**
7. **接続テスト** を押し「接続OK」が出れば完了

> コードを修正したときは「デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン：新バージョン → デプロイ」で更新してください（URLは変わりません）。

## 3. スマートフォンへの入れ方

アプリはWebページなので、インストール作業は不要です。以下のいずれかで公開してURLを配布します。

- **おすすめ**：このフォルダ一式をGoogleドライブ以外の静的ホスティング（GitHub Pages、Netlify、社内サーバーなど）に置く
- 社内WiFiのみで使う場合は、社内のWebサーバーに置くだけでも動きます

公開したURLをスマホで開き、

- **iPhone（Safari）**：共有ボタン → 「ホーム画面に追加」
- **Android（Chrome）**：右上メニュー → 「アプリをインストール」／「ホーム画面に追加」

これでアプリのアイコンから全画面で起動し、オフラインでも点検入力ができます。

## 4. 使い方

### 初回に1回だけ：点検場所の登録
**設定タブ → 点検場所の登録** で、実際の工場名を入力してください（初期値は「A工場〜E工場」）。
「＋ 点検場所を追加」で拠点を増やす、「×」で減らすこともできます。
名称は後から変更しても、過去の点検記録との紐付けは保たれます。

### 点検タブ
1. **① 点検実施日**（初期値は本日）と **② 点検場所** を選ぶ
2. **点検者**の氏名を入れる（次回から自動で入ります）
3. **③ 点検機械**を一覧から選ぶ（22機種）
4. **④ 点検項目**を **良／要注意／不良／対象外** の4択でタップ
   - 「すべて良」ボタンで一括入力 → 問題のある項目だけ変更する使い方が最速です
   - エアー圧力・硬度検査などは**測定値**も数値で記録できます
   - 項目ごとに**所見**の記入と**写真の撮影**が可能（写真はドライブに保存されリンクがシートに入ります）
   - 号機・設備No.を入れれば、同じ機械が複数台あっても別々に記録できます
5. **保存する** → 端末に保存され、自動でスプレッドシートへ送信されます

点検済みの機械には緑の枠と判定バッジ（良／要注意／不良）が付くので、点検漏れがひと目で分かります。
同じ日・同じ機械をもう一度選ぶと「編集」か「別号機として新規追加」かを選べます。

### 履歴タブ
月・場所・判定で絞り込み。行をタップすると内容を修正できます。**CSV出力**でExcelにも取り込めます。

### 進捗タブ
- 点検実施率、実施台数／対象台数、不良・要注意の件数
- 工場別の進捗バー
- **点検マトリクス**（場所 × 機械）… 〇=良 △=要注意 ×=不良 空欄=未点検
- **要対応リスト**（不良・要注意の項目一覧）

他の担当者が入力した分も見たいときは **「シートから最新取得」** を押してください。

### 設定タブ
- スプレッドシート連携URL、既定の点検者名、自動送信のON/OFF
- **点検場所の登録**：工場名の追加・変更・削除
- **点検対象設定**：各工場に実際に設置されている機械にチェック。ここが**進捗率の分母**になります（初期値は全工場に全21機種）
- バックアップ出力（JSON）、同期済みデータの端末からの削除

### オフラインのとき
画面右上の●が赤くなります。入力・保存はそのまま可能で、⇅ボタンに黄色い印（未送信あり）が付きます。
通信が回復すると自動送信され、手動で送りたいときは **⇅ボタン** を押してください。

## 5. スプレッドシートの中身

| シート | 内容 |
|---|---|
| **点検記録** | 1点検＝1行（点検日／場所／機械／号機／点検者／総合判定／不良件数／備考など） |
| **点検明細** | 1点検項目＝1行。ピボットテーブルやグラフの元データに最適 |
| **進捗ダッシュボード** | `B2` に年月（例 `2026-08`）を入れると、工場別台数・判定内訳・要対応一覧・機械別回数が自動集計されます |

同じ点検を修正して再送信した場合も、IDで照合して**上書き更新**されるため行は重複しません。
点検明細シートを使えば、Googleスプレッドシートの機能でグラフ化や共有も自由にできます。

## 6. うまくいかないとき

### 「接続テスト」が失敗する（CORSエラー）
ブラウザのログに `blocked by CORS policy` と出る場合、**Apps Script のデプロイ設定**が原因です。

1. Apps Script の画面で **デプロイ → デプロイを管理**
2. 鉛筆マーク（編集）を押す
3. **アクセスできるユーザー**が **「全員」** になっているか確認
   （「自分のみ」だとログイン画面へ転送され、アプリからは読み取れずCORSエラーになります）
4. **バージョン：新バージョン** を選んで **デプロイ**
5. 表示されたURLを設定タブに貼り直す（末尾が `/exec` であること。`/dev` は使えません）

### アプリを更新したのにスマホで古い画面のまま
ホーム画面のアイコンから一度アプリを閉じ、再度開いてください（通信できる状態で開くと自動的に最新版になります）。
それでも変わらない場合は、ブラウザの「再読み込み」または一度アイコンを削除して追加し直してください。

### 保存したデータが消えた
点検データは端末のブラウザ内に保存されます。ブラウザの「閲覧データの削除（Cookieとサイトデータ）」を行うと消えます。
定期的に **設定タブ → バックアップ出力** を行うか、スプレッドシートへ送信しておいてください。

## 7. PCでの動作確認

```bash
powershell -ExecutionPolicy Bypass -File .claude/serve.ps1
```

起動後、ブラウザで `http://localhost:5180` を開いてください（Chromeの検証ツールでスマホ表示にすると実機に近い確認ができます）。
