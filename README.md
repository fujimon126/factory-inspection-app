# 工場点検アプリ

スマートフォンのブラウザで動く工場設備の点検記録アプリです。
点検結果は端末に保存され、Googleスプレッドシートへ自動送信されて進捗が可視化されます。
電波の届かない工場内でもオフラインで入力でき、通信が回復したときにまとめて送信されます。

---

## 1. ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリの画面（点検／履歴／進捗／設定の4タブ） |
| `css/style.css` | スマホ向けデザイン（大きめのタップ領域・判定色分け） |
| `js/data.js` | **マスターデータ**。機械22種と各機械の点検項目（点検場所の名称はアプリの設定画面で登録します） |
| `js/store.js` | データ保存（端末内）とスプレッドシート送受信 |
| `js/app.js` | 画面の動作（入力・集計・CSV出力など） |
| `manifest.json` / `sw.js` / `icons/` | ホーム画面追加とオフライン動作のための設定 |
| `gas/コード.gs` | **スプレッドシート側のプログラム**（Google Apps Script） |
| `.claude/serve.ps1` | 動作確認用の簡易サーバー（PC確認用。運用には不要） |

点検項目を追加・変更したいときは `js/data.js` だけを直せば全画面に反映されます。

> **工場名について**：拠点名はプログラムに書き込まず、アプリの「設定 → 点検場所の登録」で入力する方式です。
> 入力した名称は使用する端末の中だけに保存されるため、このソースコードを公開しても社名・拠点名は外部に出ません。

## 2. スプレッドシート連携の設定（最初に1回だけ）

1. Googleドライブで**スプレッドシートを新規作成**（名前は「工場点検記録」など）
2. メニューの **拡張機能 → Apps Script** を開く
3. 表示されたコードを全部消し、`gas/コード.gs` の中身を貼り付けて保存（💾）
4. 上部の関数リストから **`初期設定`** を選び **▶ 実行**
   - 初回は権限の確認が出ます → 「権限を確認」→ 自分のアカウントを選択
   - 「このアプリは確認されていません」と出たら **詳細 → （プロジェクト名）に移動** → 許可
   - 実行すると `点検記録` `点検明細` `点検対象マスタ` `進捗ダッシュボード` の4シートが自動作成されます
5. 右上の **デプロイ → 新しいデプロイ** → 歯車から **ウェブアプリ** を選択
   - 次のユーザーとして実行： **自分**
   - アクセスできるユーザー： **全員**
   - 「デプロイ」を押し、表示された **`https://script.google.com/macros/s/.../exec`** をコピー
6. アプリの **設定タブ** を開き、コピーしたURLを「GAS ウェブアプリURL」に貼り付けて **設定を保存**
7. **接続テスト** を押し「接続OK」が出れば完了

> コードを修正したときは「デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン：新バージョン → デプロイ」で更新してください（URLは変わりません）。

## 3. スマートフォンへの入れ方

アプリはWebページなので、インストール作業は不要です。以下のいずれかで公開してURLを配布します。

- **おすすめ**：このフォルダ一式をGoogleドライブ以外の静的ホスティング（GitHub Pages、Netlify、社内サーバーなど）に置く
- 社内WiFiのみで使う場合は、社内のWebサーバーに置くだけでも動きます

公開したURLをスマホで開き、

- **iPhone（Safari）**：共有ボタン → 「ホーム画面に追加」
- **Android（Chrome）**：右上メニュー → 「アプリをインストール」／「ホーム画面に追加」

これでアプリのアイコンから全画面で起動し、オフラインでも点検入力ができます。

## 4. 使い方

### 初回に1回だけ：点検場所の登録
**設定タブ → 点検場所の登録** で、実際の工場名を入力してください（初期値は「A工場〜E工場」）。
「＋ 点検場所を追加」で拠点を増やす、「×」で減らすこともできます。
名称は後から変更しても、過去の点検記録との紐付けは保たれます。

### 点検タブ
1. **① 点検実施日**（初期値は本日）と **② 点検場所** を選ぶ
2. **点検者**の氏名を入れる（次回から自動で入ります）
3. **③ 点検機械**を一覧から選ぶ（22機種）
4. **④ 点検項目**を **良／要注意／不良／対象外** の4択でタップ
   - 「すべて良」ボタンで一括入力 → 問題のある項目だけ変更する使い方が最速です
   - エアー圧力・硬度検査などは**測定値**も数値で記録できます
   - 項目ごとに**所見**の記入と**写真の撮影**が可能（写真はドライブに保存されリンクがシートに入ります）
   - 号機・設備No.を入れれば、同じ機械が複数台あっても別々に記録できます
5. **保存する** → 端末に保存され、自動でスプレッドシートへ送信されます

点検済みの機械には緑の枠と判定バッジ（良／要注意／不良）が付くので、点検漏れがひと目で分かります。
同じ日・同じ機械をもう一度選ぶと「編集」か「別号機として新規追加」かを選べます。

### 写真の撮影と共有
不良箇所は写真で残して共有できます。

1. 点検項目の右にある **📷ボタン** で撮影（その場でカメラが起動します）
2. 保存するとスプレッドシートへ送信され、写真は**Googleドライブの「工場点検_写真」フォルダ**に保存されます
3. 履歴タブ・進捗タブの要対応リストに**写真のサムネイル**が並びます
4. サムネイルをタップすると拡大表示。**「この写真を共有」**でLINE・メール・チャットに送れます
5. 各記録の **「共有」ボタン** では、点検内容（要対応項目・測定値・備考）と写真リンクをまとめて共有できます

- 送信前（オフライン時など）は**画像そのもの**を共有します
- 送信後は**ドライブの共有リンク**を共有するため、通信量を抑えられます
- スプレッドシートの「点検明細」シートと進捗ダッシュボードの要対応リストにも写真リンクが入ります

### 要対応タブ
不良・要注意と判定した項目が**未対応のまま自動で集まります**。タブには未対応の件数が赤いバッジで表示されます。

- 不良を上に、日付の新しい順に並びます
- 場所・種別（不良のみ／要注意のみ）で絞り込めます
- **「対応完了」ボタン**を押すと入力画面が開き、次を記録できます
  - **対応日**（初期値は当日）
  - **対応担当者**（初期値は点検者名）
  - **対応内容**（例：パッキンを交換、増し締め）
  - **対応後の写真**（その場で撮影可）
  - 対応完了として記録すると、判定は自動的に**「良」**へ変更されます。変更前の判定は「当初判定」として残ります。
    スプレッドシートの判定も「良」に変わり、元の判定は**「当初判定」列**に残ります
- 記録するとリストから消え、進捗タブの要対応リストからも外れます
- 完了内容は**スプレッドシートの「対応状況」「対応日」「対応者」「対応内容」「対応写真」列**に記録されます
- 「対応完了分を表示」にチェックを入れると完了分も確認でき、**「未対応に戻す」**で戻せます
  （判定を「良」に変えていた場合は元の判定に戻ります）
- 「共有」でLINE等へ連絡、「記録を開く」でその点検記録を修正できます

### 履歴タブ
月・場所・判定で絞り込み。行をタップすると内容を修正できます。**CSV出力**でExcelにも取り込めます。

### 進捗タブ
- 点検実施率、実施項目／対象項目、不良・要注意の件数
- 工場別の進捗バー
- **点検マトリクス**（場所 × 機械）… 〇=良 △=要注意 ×=不良 空欄=未点検
- **要対応リスト**（不良・要注意の項目一覧）

他の担当者が入力した分も見たいときは **「シートから最新取得」** を押してください。

### 設定タブ
- スプレッドシート連携URL、既定の点検者名、自動送信のON/OFF
- **点検場所の登録**：工場名の追加・変更・削除
- **点検機械・点検項目の編集**：下記参照
- **点検対象設定**：各工場に実際に設置されている機械にチェック。ここが**進捗率の分母**になります（初期値は全工場に全21機種）。設定内容は同期時にスプレッドシートの「点検対象マスタ」へ送られます。

### 点検機械・点検項目の追加と変更
**設定タブ → 点検機械・点検項目の編集 → 編集画面を開く**

- **機械を追加**：画面下の「＋ 点検機械を追加」。追加した機械は自動で全工場の点検対象になります
- **機械名・アイコンの変更**：機械をタップして開き、上段の入力欄を編集（アイコンは絵文字1文字）
- **並べ替え**：↑↓ボタン。点検画面に並ぶ順番が変わります
- **点検項目の追加・変更**：機械を開いて「＋ 点検項目を追加」、項目名を入力
- **項目の種別**：
  - `判定のみ` … 良／要注意／不良／対象外の4択
  - `数値+判定` … 4択に加えて測定値を入力（単位欄に `MPa` `mg/L` などを入力）
- **削除**：項目の「×」、機械の「この機械を削除」
- **初期状態に戻す**：追加・変更をすべて破棄して22機種の初期状態へ

変更内容は端末内に保存され、点検画面にすぐ反映されます。**過去の点検記録はそのまま残ります**
（機械や項目を削除しても、記録済みのデータは消えません）。

> **複数のスマホで使う場合**：この設定は端末ごとです。全員の端末で同じ編集を行うか、
> 代表者が [js/data.js](js/data.js) の `DEFAULT_MACHINES` を直接書き換えてGitHubに反映すると、全端末の初期値が変わります。
- バックアップ出力（JSON）、同期済みデータの端末からの削除

### オフラインのとき
画面右上の●が赤くなります。入力・保存はそのまま可能で、⇅ボタンに黄色い印（未送信あり）が付きます。
通信が回復すると自動送信され、手動で送りたいときは **⇅ボタン** を押してください。

## 5. スプレッドシートの中身

| シート | 内容 |
|---|---|
| **点検記録** | 1点検＝1行（点検日／場所／機械／号機／点検者／総合判定／不良件数／備考など） |
| **点検明細** | 1点検項目＝1行。**対応状況・対応日時・対応者**の列つき。ピボットテーブルやグラフの元データに最適 |
| **進捗ダッシュボード** | `B2` に年月（例 `2026-08`）を入れると、全体KPI、**工場別進捗**、**機械別進捗**、工場×機械の「済／未／対象外」一覧、**未対応の要対応一覧**、**対応完了一覧**が自動集計されます |

### 進捗ダッシュボードの見方

- **対象項目**：各工場の「点検対象設定」でチェックされている機械の合計
- **実施項目**：対象年月内に1回以上点検された工場×機械の組み合わせ
- **未実施項目**：対象項目－実施項目
- **工場別進捗**：工場ごとの対象・実施・未実施・進捗率
- **機械別進捗**：機械ごとの対象工場・実施工場・未実施工場・進捗率（未実施の多い順）
- **工場×機械**：`済`＝実施済、`未`＝未実施、`－`＝その工場では対象外

同じ工場・同じ機械を対象月内に複数回点検しても、進捗では1項目として数えます。
初回はアプリの設定タブで **「今すぐ同期」** を押し、「点検対象マスタ」へ対象設定を送ってください。

### 色分け
判定はシート上で自動的に色分けされます。

| 判定 | 判定セル | 行全体 |
|---|---|---|
| **不良** | 赤地に白文字（太字） | 薄い赤 |
| **要注意** | 黄地に濃い文字（太字） | 薄い黄 |
| **良** | 緑地に白文字（太字） | 薄い緑 |
| **対象外** | グレー | － |

- 点検記録シートは**不良件数・要注意件数が1件以上のセル**も強調されます
- 点検明細シートは**対応状況**（未対応＝赤／完了＝緑）も色分けされ、**対応が完了した行は色が消えて白に戻ります**

同じ点検を修正して再送信した場合も、IDで照合して**上書き更新**されるため行は重複しません。
点検明細シートを使えば、Googleスプレッドシートの機能でグラフ化や共有も自由にできます。

## 6. うまくいかないとき

### ⚠️ 最重要：コードを直したら「再デプロイ」が必要です
Apps Script のウェブアプリは、**コードを保存しただけでは反映されません**。
デプロイした時点のバージョンが使われ続けるため、アプリからの送信は古いコードで処理されます。

コードを貼り替えたら、**毎回**次の操作を行ってください（URLは変わりません）。

1. 右上の **デプロイ → デプロイを管理**
2. 鉛筆マーク（編集）をクリック
3. **バージョン：新バージョン** を選択
4. **デプロイ** をクリック

「対応状況が書き込まれない」「新しい列が増えない」は、ほぼこの操作漏れが原因です。

### 進捗ダッシュボードの要対応リストに何も出ない
次の順に確認してください。

1. 上記の**再デプロイ**を行う
2. 関数 **`初期設定`** を実行（既存データの対応状況が自動で「未対応」に埋められます）
3. それでも出ない場合は関数 **`修復_対応状況`** を単独で実行

なお、表がずれて `#REF!`（結果が重複しています）と出る場合は、ダッシュボードの表の配置が古いままです。
最新のコードでは各表を別の列（A・D・G・J・S列）に配置して衝突を防いでいます。`初期設定` で作り直されます。

### 「接続テスト」が失敗する（CORSエラー）
ブラウザのログに `blocked by CORS policy` と出る場合、**Apps Script のデプロイ設定**が原因です。

1. Apps Script の画面で **デプロイ → デプロイを管理**
2. 鉛筆マーク（編集）を押す
3. **アクセスできるユーザー**が **「全員」** になっているか確認
   （「自分のみ」だとログイン画面へ転送され、アプリからは読み取れずCORSエラーになります）
4. **バージョン：新バージョン** を選んで **デプロイ**
5. 表示されたURLを設定タブに貼り直す（末尾が `/exec` であること。`/dev` は使えません）

### 「型付きの列でセルの数値形式を設定することはできません」と出る
シートが Googleスプレッドシートの **「テーブル」** に変換されていると列の型が固定され、
スクリプトから表示形式（`setNumberFormat`）を変更できないために起こります。

Apps Script はシートへの変更をいったん溜めてからまとめて適用するため、
**エラーは書式設定を書いた行ではなく `SpreadsheetApp.flush()` の行で発生する**のが特徴です。

最新版のコードでは、データシートへの表示形式の設定そのものを**削除**しました
（集計は点検日の期間で行うため、表示形式は結果に影響しません）。
最新のコードに貼り替えれば発生しません。

通常の表に戻したい場合は、データ範囲を右クリック → **「テーブル」→「範囲に変換」** で戻せます。

### 進捗ダッシュボードの `B2` に年月を入れても集計されない
関数 **`診断_データ形式`** を実行し、画面下部の「実行ログ」を確認してください。
点検日が **「文字列 ← 要修復」** と表示された場合は、関数 **`修復_日付と年月`** を実行すると直ります。
`2026-08` という値を、スプレッドシートが**自動的に日付データ（2026年8月1日）に変換**してしまうことが原因です。
文字列どうしの照合ができなくなり、集計が0件になります。

**対処**：Apps Script のコードを最新版に貼り替えて保存し、関数 **`初期設定`** を実行してください。
ダッシュボードが作り直され、過去データの点検日・年月も自動で修復されます。

なお、**`B2` を空欄にすると全期間が集計**されます。年月を入れる場合は `2026-08` の形式です。

### アプリを更新したのにスマホで古い画面のまま
ホーム画面のアイコンから一度アプリを閉じ、再度開いてください（通信できる状態で開くと自動的に最新版になります）。
それでも変わらない場合は、ブラウザの「再読み込み」または一度アイコンを削除して追加し直してください。

### 保存したデータが消えた
点検データは端末のブラウザ内に保存されます。ブラウザの「閲覧データの削除（Cookieとサイトデータ）」を行うと消えます。
定期的に **設定タブ → バックアップ出力** を行うか、スプレッドシートへ送信しておいてください。

## 7. PCでの動作確認

```bash
powershell -ExecutionPolicy Bypass -File .claude/serve.ps1
```

起動後、ブラウザで `http://localhost:5180` を開いてください（Chromeの検証ツールでスマホ表示にすると実機に近い確認ができます）。
